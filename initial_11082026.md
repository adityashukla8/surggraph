## 1. What we're building (one paragraph)

**SurgGraph** is an autonomous multi-agent surgical AI system for the **All Things Agentic Hackathon** (Google Cloud / Devpost). Given a recorded surgical case, it (a) builds a **Living Surgical State** graph from video, (b) plans a mission with candidate trajectories, potential future complications or errors, (c) rehearses those trajectories against a symbolic world model to predict consequences, (d) monitors execution against the chosen plan, (e) autonomously detects divergence (a surgical error or complication signal), (f) actively inspects the patient's preoperative imaging and retrieves literature to diagnose the divergence, and (g) autonomously re-plans and recovers. The tagline for the tool's purpose:

> **"I have a goal in a dynamic environment; predict consequences before acting, act, observe the new state, and recover."**

The 4-minute demo shows a **judge dropping a video into a bucket → the fleet autonomously running the full plan → divergence → active CT inspection + RAG → recovery re-plan → structured artifact written to an external system**, with every autonomous decision traced.

## 4. Procedure & data plan (RARP + composed preop MRI)

### 4.1 Procedure
**Robot-Assisted Radical Prostatectomy (RARP)** — specifically the dorsal vascular complex suturing task from **SAR-RARP50**.

**Why RARP over cholecystectomy or SpineDepth:**
- **SAR-RARP50 + SEDMamba is the only public dataset with native, frame-level, real surgical error labels** — 24 error types across 48 videos, >970,000 frames annotated (needle drop/slip, tissue damage, incorrect angle grasping needle, excessive force, etc.). This is the richest real divergence signal available anywhere in public surgical data.
- Cholecystectomy would force us to synthesize the complication signal (bile-duct-injury proxy) — weaker demo.
- SpineDepth has real video↔CT linkage but no native error labels; large SVO files; requires ZED SDK; cadaveric-only.
- RARP's tradeoff is honest: no same-patient preop MRI is public → the preop-imaging beat is composed and clearly disclosed.

### 4.2 Data sources

**Intraoperative video + error labels (REAL, primary):**
- **SAR-RARP50**: 50 in-vivo RARP suturing videos, 1280×720 @ 60 fps, action + instrument segmentation labels. Host: UCL Research Data Repository (`rdr.ucl.ac.uk`, project 191091).
- **SEDMamba error labels**: 48 of the 50 videos annotated frame-level for 24 error types (binary normal/error per frame, temporal boundaries). Host: UCL RDR article 27992702 + `github.com/wzjialang/SEDMamba`.
- **Plan:** download **one video** (with matching annotations + error labels) end-to-end. Do not attempt the full 50-video corpus.

**Preop MRI (COMPOSED, disclosed synthetic linkage):**
- Use a single prostate MRI case from **PROSTATEx** or **PI-CAI** (open, downloadable, MRI-only).
- The MRI patient is **not** the RARP video patient. **The demo must state this on-screen and the README must document it.** This is ethically required and consistent with dataset licenses.
- Fabricate a **single synthetic patient record** (name, MRN, allergies, brief history, a plausible clinical finding on the MRI like "left peripheral zone lesion, PI-RADS 4, close to left neurovascular bundle") that ties the MRI to the video narratively.

**Guidelines / literature (REAL, for RAG):**
- **Europe PMC REST API** (no key required).
- **NCBI E-utilities / PubMed** (free; API key raises rate limit).
- Pre-cache ~15–20 abstracts on RARP complications (positive surgical margins, neurovascular bundle injury, urethral anastomosis leak, hemostasis in the dorsal vascular complex) so the demo runs without live network dependency.
- Optional: **openFDA + RxNorm** for a drug-lookup sub-beat if we add a "give tranexamic acid for bleeding" moment.

### 4.3 Divergence scenario grounded in real annotations

**Primary scenario (uses SEDMamba's real labels):**
1. Agent selects "complete dorsal vascular complex suturing" as the mission. (based on the data available)
2. Playback of the SAR-RARP50 video with SEDMamba frame labels overlaid on the state graph.
3. At the first real error-labeled frame (e.g., "incorrect angle grasping needle" or "excessive force"), the Monitor Agent fires the divergence event based on the **real ground-truth label**, not a fabricated one.
4. Recovery: Verifier confirms divergence; Imaging Agent actively inspects the patient's MRI (segments the prostate + neurovascular bundle, checks proximity to the current suturing region); Literature Agent retrieves relevant guidelines from web search litrature (if time persists, we need to update this to RAG); Planner proposes a corrected trajectory; Router writes the FHIR DocumentReference + fires alert.

**Why this is defensible:** the divergence signal is a real annotation from a peer-reviewed dataset (SEDMamba, IEEE RA-L 2024, arXiv:2406.15920), not a script.

### 5.2 Agent topology

Named agents, each with a scoped tool set. Delegation happens via ADK's coordinator pattern.

1. **Orchestrator (root ADK agent)** — receives video from gcs, opens the case, dispatches sub-agents, owns the state machine and the recovery loop.
2. **Scene Graph Builder Agent** — takes windowed frames from the SAR-RARP50 video, calls Gemini 3.5 Flash vision to emit structured JSON (`{instruments, anatomy, actions, phase, timestamp, confidence}`), writes nodes/edges into the Living Surgical State graph. Uses SAR-RARP50's ground-truth action/instrument annotations as a validation sidecar (not as the primary source — the *agent* extracts).
3. **Workflow/surgery/mission Planner Agent** — consumes patient record + MRI-derived risk flags + current state → generates candidate trajectories with expected state transitions and risk annotations.
4. **World Model Agent (symbolic)** — rolls each candidate trajectory forward on the current graph state using hand-authored state-transition rules + risk scores. Emits a predicted terminal state and a risk vector per candidate. **Not generative video. Not GPU-dependent.** Cite MeWM, H-WM, SurgWorld as *design references only*.
5. **Safety Critic Agent** — attacks each rehearsed plan (ex. "what could go wrong under this trajectory given the MRI-flagged proximity to the left NVB?" this should not be hardcoded); returns a ranked recommendation with reasoning.
6. **Monitor Agent (Sentinel)** — watches the running state graph against the selected plan; fires a divergence event when the observed state (SEDMamba-labeled real error frame) violates expected transitions.
7. **Imaging Agent (active perception)** — on divergence, autonomously chooses which MRI slice/region to inspect. Tools it can call: `list_dicom_slices(series_id)`, `window_slice(slice_id, window, level)`, `run_totalsegmentator(volume, roi_subset=[...])`, `measure_distance(structure_a, structure_b)`. **The agent decides which tools to call in what order — this is the "active perception" beat.** Feel free to update/change the tools mentioned above as per research.
8. **Literature/RAG Agent** — queries in realtime websearch preferrably, or else pre-cached Europe PMC abstract corpus (and openFDA if relevant) for the specific complication signal; returns citations. This should not be hardcoded.
9. **Verifier Agent (fail-closed)** — before any external action, verifies every claim in the proposed artifact against graph edges + retrieved evidence. Blocks unsupported claims. Emits a structured "block" event when it refuses.
10. **Recovery Planner Agent** — proposes 2–3 recovery trajectories; World Model + Safety Critic re-run on these; one is selected.
11. **Action Router Agent** — makes the explicit autonomous routing decision (write-only / write+alert / no-action / human-escalate). Calls FHIR write tool + readback verify + alert tool. Credentials via Secret Manager.
12. **Debrief Agent (optional, cut early if behind)** — emits a post-mission structured artifact (what plan was chosen, what diverged, what recovery was chosen, edge-path evidence).

### 5.3 The Living Surgical State (schema sketch) example

```
CaseState {
  case_id, timestamp, procedure = "RARP"
  patient: { synthetic_record_ref, mri_series_ref, risk_flags[] }
  procedure_state: { phase, step, completed_actions[], expected_next[] }
  entities: { instruments[], anatomy[], actors[] }
  relations: { spatial[], action[], interaction[] }  // <instrument, verb, target>
  mission: { goal, active_plan, rejected_alternatives[], contingency_branches[] }
  predictions: { rehearsed_futures[], predicted_risks[] }
  uncertainty: { anatomy_conf, state_conf, risk_conf }
  evidence: { video_refs[], mri_refs[], literature_refs[], guideline_refs[] }
  history: { previous_states[], deviations[], recoveries[], agent_actions[] }
  provenance: { every element carries source_agent + source_tool + timestamp }
}
```

**Principle:** agents do not carry the whole case in their prompt context. They query the state via tools. This gives persistent memory, auditable reasoning, and clean OpenTelemetry traces.

### 5.4 Event flow

```
video uploaded to gs://surggraph-cases/{case_id}/
    → GCS video. Pub/Sub topic if time permits at the end `surggraph-case-events`
    → Orchestrator (Cloud Run) picks up the event
    → SceneGraphBuilder streams frames → Gemini Flash → state graph
    → MissionPlanner + WorldModel + SafetyCritic (fan-out, parallel)
    → Plan selected → Monitor starts
    → SEDMamba real-error frame reached → divergence fires
    → ImagingAgent + LiteratureAgent (fan-out, parallel) → diagnose
    → RecoveryPlanner → WorldModel + SafetyCritic → recovery selected
    → Verifier fail-closed check
    → ActionRouter → FHIR write + readback + Slack page
    → DebriefAgent emits artifact
```

### 5.5 UI — the 6-tile layout the user wants

The frontend is a single-page dashboard, deployed alongside Cloud Run.

1. **Raw video** (top-left) — SAR-RARP50 clip playing, with a SWAG-style buffer slider so the user can scrub.
2. **Segmented / annotated video** (top-right) — same video with SAR-RARP50 ground-truth masks/labels overlaid (this is the "pre-recorded CV results" tile).
3. **Living State Graph** (middle-left) — the graph, visually differentiated by node/edge type:
   - Agents (rounded rectangles, color per agent)
   - Plans / predicted trajectories (dashed edges)
   - Actions (solid edges)
   - Actual observed trajectory (bold solid)
   - Revised trajectory after recovery (colored differently)
   - others as needed
4. **Manual event input** (middle-right) — a text box the user can use to inject a complication signal ("blood loss 400 ml", "giving tranexamic acid") that triggers the divergence pipeline. Also shows the Monitor Agent's autonomous divergence firing when SEDMamba labels hit.
5. **Triggered information retrieval panel** (bottom-left) — live view of the Imaging Agent navigating the MRI (slice IDs being requested, structures being segmented) and the Literature Agent's RAG hits scrolling in with citations. This is the tile that most viscerally shows "the agents are working autonomously right now."
6. **Autonomous action log + external artifact viewer** (bottom-right) — every routing decision the ActionRouter makes; the FHIR DocumentReference JSON that gets written; the readback response; the alert message that fired.

## 9. Design principles (read before making tradeoffs)

- **Real over impressive.** Prefer a small real thing over a big fake thing. If a beat is composed, disclose it.
- **Autonomy is a shape, not a label.** The demo must show: event trigger without human prompt → delegation → tool-choice by the agent → verification → cross-app action. If a beat doesn't show one of these, it doesn't earn the "autonomy" score.
- **Fail-closed by default.** Every claim must trace to a graph edge or a cited source. When in doubt, block.
- **State is queried, not carried.** Agents call tools to read/write the state. This is what makes traces coherent.
- **Every decision is provenanced.** Every node, edge, and action carries `source_agent + source_tool + timestamp`.
- **The graph is the memory, the guardrail, and the audit trail.** One structure, three jobs. Say this out loud in the pitch.
- **Do not train anything.** No fine-tuning. No GPU. Gemini Flash + pretrained public checkpoints as tools + symbolic reasoning.
- **Two external systems minimum for Taskmaster.** FHIR + Slack. If either fails silently, the score fails silently.
