## 2. What SurgBot actually is

SurgBot is a **voice/text conversational case-review agent**, built as an additive layer on top of SurgGraph's existing autonomous surgical-analysis pipeline — it never touches or modifies that pipeline, it only *reads* the graphs SurgGraph already produced. Where SurgGraph runs fully autonomously on one case in real time (the "Taskmaster" side of this project), SurgBot is the human-facing counterpart: a surgeon or patient-safety reviewer sits down after the fact, talks through what the autonomous system found on one *or many* cases, agrees or disagrees with its reasoning, leaves coaching notes, and produces a signed-off review document — while SurgBot itself gets measurably better at working with that specific reviewer over time (the "Collaborative Partner" side).

**The 6-phase conversation it runs** (not a rigid script — you can jump around, as this transcript shows by skipping straight past the "walk phase by phase" offer into error review):
1. **Case framing** — orient the reviewer to a case (or list all cases).
2. **Chronological graph walkthrough** — phase-by-phase summary.
3. **Error-and-complication review** — causal chains: what error, what complications, what literature backs it, is it plausible.
4. **Corrective proposals & divergences** — what the system recommended vs. what actually happened.
5. **Synthesis & case review document** — drafts a structured, approvable document from the whole conversation.
6. **Cross-session pattern review** — "have I shown any patterns across my past sessions" — backed by real Memory Bank data, never fabricated.

Plus a standing cross-case capability available at any point ("what's the most common error across all cases") for aggregate questions that don't belong to any single case.

## 3. The agents and tools actually at play

Everything runs on **Gemini 3.5** (no exceptions — an earlier Live-API-voice architecture split "voice model" from "reasoning model"; that was fully retired in favor of a classic Speech-to-Text → LLM → Text-to-Speech pipeline, so every reasoning step, voice or typed, is the same model).

| Component | Role | Deployed as |
|---|---|---|
| **SurgBot Orchestrator** (was "SurgBot Root") | The one agent you actually talk to. Holds the 8 tools below, drives the phase script, decides when to dispatch to a subagent. | Agent Runtime reasoning engine, STABLE `AdkApp` |
| **Error Chain Review Agent** | Given one flagged error, explains the causal mechanism, checks plausibility, and cites real retrieved literature (never a fabricated citation). | Separate Agent Runtime reasoning engine, deployed with Agent Identity |
| **Case Review Agent** (was "Synthesis") | Drafts the structured review document from the whole conversation + recorded feedback. | Separate Agent Runtime reasoning engine, deployed with Agent Identity |
| **Cross-cases Coaching Agent** (was "Pattern Insight") | Turns real Memory Bank retrieval results into a spoken pattern summary — reports "no history yet" honestly rather than inventing a pattern. | Separate Agent Runtime reasoning engine, deployed with Agent Identity |
| **Speech-to-Text** | Cloud Speech v2, Chirp 3 model, real streaming transcription of your held-mic audio. | Cloud Speech API (not an "agent," a plain API call, disclosed as such) |
| **Text-to-Speech** | Cloud TTS, Chirp 3 HD voice ("Kore"), streams the reply back as audio sentence-by-sentence. | Cloud TTS API |

**The Orchestrator's 8 tools**, all plain async Python functions (a deliberate, disclosed exception to this codebase's usual "no tools, just structured prompting" pattern, because a live conversation's next question genuinely can't be pre-scripted):
`list_accessible_cases`, `load_case_graph`, `get_phase_detail`, `get_error_statistics_across_cases`, `review_error_chain` (dispatches to the Error Chain Review Agent), `review_proposal_divergence`, `record_feedback`, `draft_review_document` (dispatches to the Case Review Agent), `retrieve_reviewer_patterns` (dispatches to the Cross-cases Coaching Agent).

## 4. GEAP (Gemini Enterprise Agent Platform) services actually in use

- **Agent Runtime** — hosts all 4 Gemini agents above as real, independently deployed reasoning engines (not one monolith).
- **Agent Registry** — makes those 4 agents discoverable as real registered services (fixed today — two of them had never been registered, and two were pointing at stale/deleted engines from earlier redeploys, which is what was breaking the console's Topology view).
- **Agent Identity** — SPIFFE-based identity, auto-provisioned on the 3 subagents (the Orchestrator itself runs under a plain service account instead, a disclosed, deliberate exception — its own outbound calls were incompatible with Agent Identity).
- **Memory Bank** — real, managed cross-session memory. A fact gets written only on document approval (you can see it happen in this transcript's Firestore/memory-bank log lines), and retrieval is never fabricated — "no history yet" is reported as-is when that's the honest answer.
- **Model Armor** — screens drafted review documents for injected/unsafe content before they become approvable. Confirmed working via a deterministic test earlier; its per-agent console dashboard is a separate, still-open item (see `docs/qa_log.md` — a real Google-side backend limitation, not something wrong in this session).
